# Findings: RAG's Role in Enterprise Knowledge QA

## Research scope
This file covers RAG's role in enterprise knowledge question answering, specifically grounding, freshness, provenance, access control, and operational considerations. It does not assess vendors beyond the Microsoft Learn Azure AI Search overview requested, nor does it claim that RAG guarantees factual correctness or security by itself.

## Key findings
- **Grounding:** The original RAG paper describes combining a pretrained model's parametric memory with a non-parametric memory (a dense Wikipedia index accessed by a neural retriever). It reports improved performance on several knowledge-intensive tasks and more specific, diverse, and factual generation than a parametric-only baseline. This supports RAG as a way to condition answers on retrieved evidence, not as a guarantee that every answer is correct. Microsoft likewise characterizes RAG as grounding responses in proprietary content and emphasizes retrieval relevance, chunking, hybrid search, and ranking as determinants of grounding quality.
  Source: [Lewis et al., arXiv paper](https://arxiv.org/abs/2005.11401); [Microsoft Learn, RAG and Generative AI - Azure AI Search](https://learn.microsoft.com/en-us/azure/search/retrieval-augmented-generation-overview)
- **Freshness:** Lewis et al. identify updating world knowledge as an open problem for parametric models and motivate explicit non-parametric memory. In enterprise systems, external indexes or knowledge sources can be refreshed independently of model weights. Microsoft documents incremental indexing as a way to keep indexed content fresh, while also describing direct querying of some remote sources. Freshness therefore depends on ingestion/update cadence, source connectivity, and index behavior; RAG alone does not ensure that the latest policy or record is available.
  Source: [Lewis et al., arXiv paper](https://arxiv.org/abs/2005.11401); [Microsoft Learn, RAG and Generative AI - Azure AI Search](https://learn.microsoft.com/en-us/azure/search/retrieval-augmented-generation-overview)
- **Provenance:** The original paper explicitly notes that providing provenance for model decisions is an open research problem. Microsoft describes citation tracking and query activity logs for agentic retrieval, and structured responses that can include grounding data, citations, and execution metadata. These features can make evidence traceable, but citations only help if the retrieved passages are relevant, correctly attributed, and retained through answer generation; the sources do not establish that citations prove entailment or correctness.
  Source: [Lewis et al., arXiv paper](https://arxiv.org/abs/2005.11401); [Microsoft Learn, RAG and Generative AI - Azure AI Search](https://learn.microsoft.com/en-us/azure/search/retrieval-augmented-generation-overview)
- **Access control:** Microsoft identifies granular access control as a core RAG challenge and says users and agents should retrieve only authorized content. Its overview describes document-level security trimming, inherited Microsoft Entra ID permission metadata for indexed Azure Storage content, query-time filters for other sources, SharePoint permission inheritance for remote queries, and private endpoints. These are implementation capabilities, not evidence that a deployed system is secure by default: identity propagation, permission synchronization, filter correctness, and testing remain operational responsibilities.
  Source: [Microsoft Learn, RAG and Generative AI - Azure AI Search](https://learn.microsoft.com/en-us/azure/search/retrieval-augmented-generation-overview)
- **Operational considerations:** Enterprise RAG must balance query understanding, multi-source access, limited context windows, response-time expectations, and security. Microsoft contrasts agentic retrieval (LLM-based query planning, multiple parallel subqueries, structured responses) with classic RAG (single-query orchestration, simpler architecture and fewer components). It also highlights content preparation (chunking, vectorization, OCR/document extraction), hybrid retrieval, semantic ranking, result limits, timeouts/retries, and relevance tuning. These are design choices and trade-offs; the overview's product-specific performance descriptions should not be treated as independent benchmarks for every workload.
  Source: [Microsoft Learn, RAG and Generative AI - Azure AI Search](https://learn.microsoft.com/en-us/azure/search/retrieval-augmented-generation-overview)

## Evidence and uncertainty
The original paper is primary research evidence for the RAG architecture, its evaluated task results, and the authors' stated open problems around provenance and updating knowledge. It is not an enterprise deployment study. The Microsoft Learn page is a product overview and documents Azure AI Search capabilities and design considerations; its claims are vendor documentation, not a neutral comparative evaluation. The evidence supports the general role of retrieval as an external grounding mechanism and identifies practical dependencies, but does not quantify enterprise QA accuracy, freshness SLAs, security effectiveness, or operational cost. Assumptions to avoid: that retrieved context is necessarily authoritative/current; that citations guarantee faithful support; or that access-control features eliminate configuration and governance risk.
