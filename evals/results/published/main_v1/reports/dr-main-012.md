# 企业 RAG 系统中的提示注入风险与防护方案

## 背景

检索增强生成（RAG）系统把用户问题与从企业知识库、连接器或外部来源检索到的内容共同交给大语言模型处理。提示注入的核心问题是指令与数据边界模糊：模型可能把用户输入或检索文档中的恶意文本当作应执行的指令。直接提示注入来自用户对话输入；间接提示注入则藏在网页、邮件、附件、代码注释或知识库文档等模型随后读取的内容中。OWASP 的提示注入指南还列出文档投毒、多模态内容、编码/混淆等攻击形式，以及提示泄露、敏感数据外传和工具/API 未授权操作等潜在影响。[OWASP LLM Prompt Injection Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)

风险不只取决于模型是否识别恶意指令，也取决于它能检索哪些数据、能调用哪些工具，以及下游是否直接信任模型输出。因而，企业 RAG 应把数据访问、内容处理、工具执行和输出消费视为不同的安全边界，采用纵深防御。

## 关键发现

1. **间接注入扩大了传统输入边界。** 恶意内容可经摄取、解析、索引和检索进入上下文；只检查用户输入不足以覆盖文档、网页、邮件及多模态载体。OWASP 将指令/数据边界模糊视为提示注入的根本问题，并列出 RAG 文档投毒等攻击类型。
2. **数据隔离与内容过滤解决不同问题。** Microsoft Learn 的 Azure AI Search 安全培训将按用户限制文档级访问列为安全重点；这类控制回答“谁能读什么”。Azure AI Content Safety 文档说明其可处理文本和图像并标记潜在不适宜内容；这类筛查回答“内容是否具有某类风险”，不能替代身份授权或租户隔离。
3. **工具权限决定攻击影响上限。** 若模型可触达企业连接器、API 或有副作用的操作，提示注入可能从错误回答升级为未授权操作。工具授权应在执行边界强制实施，而不是只依赖系统提示要求模型自我约束。此处的具体授权设计属于风险导向的工程建议，本轮未取得专门官方来源核验。
4. **输出验证是补充控制，不是事后万能补救。** 对敏感信息、结构化输出和下游动作进行校验可降低不安全结果被消费的风险；但它不能撤销已经发生的越权检索或外部工具副作用。具体验证机制属于工程建议，非本轮来源直接证明的官方要求。
5. **现有证据支持定性控制映射，不支持效果量化。** 本轮可核验来源页面共 4 个，少于用户要求的至少 5 个；NIST 与 Google Cloud 目标官方页面未成功核验。工具授权和输出验证的具体方案因此作为风险导向的工程建议，而非归因于未核验的官方规范。

## 证据与分析

### 风险链与控制边界

典型间接注入链条可概括为：攻击者影响外部内容 → 内容被摄取或检索 → 与可信指令混入模型上下文 → 模型服从恶意指令 → 产生信息披露或工具动作。该链条是对 OWASP 所列攻击类型和影响的归纳，并非每个部署都具备全部环节。直接注入从用户输入开始；间接注入则把攻击面扩展到数据源、解析器、索引、检索和会话记忆。

| 控制层 | 主要目标 | 适用方案 | 不能替代的控制 |
|---|---|---|---|
| 数据隔离与检索授权 | 限制主体可见的数据 | 在检索路径按已验证的用户/组权限实施文档级过滤；明确租户边界。默认拒绝等具体机制属于工程设计建议，需结合平台验证 | 内容过滤不能代替访问控制；提示词不能代替服务端授权 |
| 内容过滤 | 识别或降低不可信内容风险 | 在摄取和/或检索阶段筛查文本、图像及解析结果；保留来源与信任标签；对高风险内容隔离或人工复核。此为建议，现有来源未证明分类器能完整检测提示注入 | 分类器不能证明内容安全，也不能决定用户是否有权读取 |
| 工具授权 | 限制模型可造成的外部影响 | 工具按任务和用户身份授权；最小权限、允许列表、参数/目标校验；高影响或不可逆操作设置独立确认。均为风险导向的工程建议，非本轮已核验的官方规范 | 模型自我声明或提示词约束不能替代执行端权限检查 |
| 输出验证 | 限制生成结果及下游消费风险 | 检查敏感信息、输出结构、策略约束和下游动作参数；拒绝不符合约束的结果并记录审计。具体规则需在目标系统验证 | 不能补救已发生的越权读取或工具副作用 |

### 取舍与适用场景

数据隔离是多租户和敏感知识库的首要边界，因为错误检索本身就可能造成披露；内容过滤适合外部网页、用户上传文件和复杂文档处理，但可能存在漏检、误报和覆盖模态不足。工具授权对连接数据库写入、企业 API 或其他有副作用工具的代理尤其关键；输出验证适用于所有下游会消费模型结果的场景，但应放在执行前的授权之后，不能作为唯一防线。

四类控制互补而不可互换。内容筛查可能降低恶意内容进入上下文的机会，但无法保证识别所有编码、混淆或多模态指令；权限过滤限制数据可见性，却不能阻止有权访问的文档携带恶意指令。工具授权限制动作能力，输出验证检查结果，两者分别在执行前和结果交付/下游消费前发挥作用。纵深防御会增加策略维护、权限同步、审计和延迟等成本；本轮来源没有提供这些成本或控制效果的量化数据。

### 证据强度与不确定性

OWASP 页面支持提示注入类型、攻击面和潜在影响的定性归纳。Microsoft Learn 安全培训支持文档级访问控制作为搜索安全重点；Azure AI Content Safety 官方文档支持文本/图像风险标记能力概述。Azure AI Search 文档入口虽已检索到，但本轮未核实具体多租户过滤、租户字段或权限同步实现，不能据此推断实现细节。NIST AI 600-1 与 Google Cloud 目标页面未成功核验，因此本报告不把工具授权、最小权限或输出验证建议归因于这些来源。当前证据不足以给出攻击概率、误报/漏报率、性能成本或风险排名。

## 建议

1. **先建立数据边界。** 将租户、用户/组权限和文档 ACL 纳入检索授权路径；在服务端依据可信身份上下文过滤候选文档，避免把权限判断交给模型。权限缺失、过期或无法验证时采取何种默认策略（例如默认拒绝）应作为风险导向的设计决策，并在目标平台验证。具体字段、过滤表达式和权限同步方式需按所用检索平台核实。
2. **把检索内容视为不可信输入。** 对外部来源、用户上传文件和解析结果记录来源、租户、信任级别与时间；在摄取和检索阶段按风险筛查内容，必要时隔离、人工复核或排除。过滤器应覆盖实际启用的文本/图像处理链路，并通过对抗样本测试；不要把内容安全分类器当作提示注入的完整检测器。
3. **在工具执行端实施授权。** 仅暴露完成任务所需的工具和操作；将授权绑定到用户身份、任务范围和资源对象，采用允许列表、参数校验、速率/额度限制及审计。对写入、发送、删除、权限变更等高影响动作设置独立确认或审批。以上为工程建议，需结合业务风险和工具能力验证；工具服务端必须再次验证权限，不能信任模型生成的调用参数。
4. **验证输出与动作参数。** 对结构化输出执行 schema 校验；对可能泄露的敏感信息执行策略检查；对下游动作重新校验目标、参数和授权。校验失败时拒绝执行或转人工处理，并记录可追溯日志。具体规则和阈值应由目标系统测试确定。
5. **按攻击链持续验证。** 建立覆盖直接注入、文档投毒、跨租户检索、敏感信息披露和工具滥用的测试集；分别验证检索授权、内容筛查、工具执行和输出校验是否在各自边界生效。监控拒绝、异常检索、工具调用和策略绕过事件，定期复核权限与数据来源。
6. **分阶段上线并度量。** 先对高敏感数据和高副作用工具启用强制控制，再逐步扩展；在目标环境测量误报/漏报、延迟、权限同步时效和人工复核负担。现有来源没有提供可直接套用的阈值，应由企业基于风险容忍度和业务测试确定。

## 局限性

本轮 findings 中只有 4 个不同且成功核验的来源页面，未达到用户要求的至少 5 个链接；NIST 与 Google Cloud 官方目标页面未成功取得。本轮未取得更多可核验来源，因此报告明确保留来源不足，不以无关链接补数。Azure AI Search 证据粒度有限，未核实具体多租户实现；工具授权和输出验证建议属于工程推论，尚缺本轮可核验的专门官方来源。没有量化攻击成功率、控制效果、误报/漏报、成本或延迟数据，结论需结合目标系统架构、数据敏感度、连接器和工具副作用进一步验证。
