# RAG 服务年度成本模型：100 万次请求

## 背景

本报告建立一个可复算的年度 RAG 服务成本模型，覆盖模型推理、Embedding、向量数据库、缓存与计算资源。工作负载按年处理 1,000,000 次请求、每次平均 4,000 个输入 Token 和 500 个输出 Token；向量库包含 1,000,000 个文档块，每月更新 10%。价格基准日期按用户指定的运行日期 **2026-10-15** 记录，但本轮官方页面证据不足以证明所有页面价格在该日有效。下文将页面可见价格、变量公式和纯示例假设严格区分。

## 关键发现

- 年度推理工作负载为 **40 亿输入 Token、5 亿输出 Token**。若缓存命中率假设为 70%，则 700,000 次命中、300,000 次未命中；在“命中即返回、不调用生成模型”的简化假设下，未命中推理量为 12 亿输入 Token和 1.5 亿输出 Token。
- Embedding 量取决于是否把初始建库计入首年：假设初始全量嵌入 1,000,000 块、每月重嵌入 100,000 块，则首年共 2,200,000 块，稳态年度更新为 1,200,000 块。平均块长和 Embedding 单价未确认，故以公式估算。
- Pinecone findings 页面可见存储价格为 **$0.33/GB/月**，但 1,000,000 个文档块不能直接换算为 GB。按 10/100/1,000GB 的透明容量情景，单纯存储年费分别为 **$39.60/$396/$3,960**；Standard 最低消费为 $50/月，按页面口径最低年消费 $600，且最低消费可抵扣用量，不能与存储费机械相加。
- 缓存与计算资源的官方 findings 提供计费单位，但没有足以计算本工作负载的区域单价、实例规格或用量。相应成本必须用变量公式或明确标注的示例假设表达。
- 因模型/API、AWS 实际单价及向量库实际容量等关键参数缺失，当前不能给出可信的单一总年成本。示例金额仅用于展示公式敏感性，不是报价。

## 证据与分析

### 工作负载与缓存假设

年度总量：

- 输入 Token：`1,000,000 请求 × 4,000 Token = 4,000,000,000 Token/年`。
- 输出 Token：`1,000,000 请求 × 500 Token = 500,000,000 Token/年`。
- 总推理 Token：`4,000,000,000 + 500,000,000 = 4,500,000,000 Token/年`。

缓存命中率是建模假设，不是实测数据。基准取 **70%**，并以 30% 和 90% 做敏感性分析。假设命中请求直接返回缓存结果、不触发生成模型；未命中请求仍完整消耗 4,000 输入和 500 输出 Token。语义缓存可能仍需 Embedding、检索或校验，这些成本不视为零。

| 缓存命中率 | 命中请求/年 | 未命中请求/年 | 未命中输入 Token | 未命中输出 Token |
|---:|---:|---:|---:|---:|
| 30% | 300,000 | 700,000 | 2,800,000,000 | 350,000,000 |
| **70%（基准）** | **700,000** | **300,000** | **1,200,000,000** | **150,000,000** |
| 90% | 900,000 | 100,000 | 400,000,000 | 50,000,000 |

### 分项成本模型

**1. 模型推理**

本轮 OpenAI 官方页面未提供可核验的 API 模型逐项单价；ChatGPT Business 席位价格不能当作 API 价格。设 `P_in`、`P_out` 分别为所选模型每百万输入/输出 Token 的美元单价，`h` 为缓存命中率，则：

`C_infer(h) = (1-h) × [4,000 × P_in + 500 × P_out]` 美元/年。

公式中的系数 4,000 和 500 分别表示无缓存时年度输入、输出 Token 数折算为“百万 Token”后的数量。基准命中率 70% 时：`C_infer = 1,200 × P_in + 150 × P_out`。30% 和 90% 命中率时分别为 `2,800 × P_in + 350 × P_out`、`400 × P_in + 50 × P_out`。

仅作敏感性演示，若假设 `P_in=$1/百万 Token`、`P_out=$4/百万 Token`（**纯示例，不是官方报价，也未核实为 2026-10-15 价格**），则 30%/70%/90% 命中率下推理成本分别为 **$4,200/$1,800/$600/年**。实际预算必须替换为目标模型在目标日期的官方 API 单价，并核对缓存 Token、重试、系统提示和多轮调用的计费口径。

**2. Embedding**

假设每月更新 1,000,000 块的 10%，即 100,000 块；全年更新 1,200,000 块。若首年还需对全库初始嵌入 1,000,000 块，则首年处理 2,200,000 块；稳态年度仅计更新则为 1,200,000 块。设每块平均 `T_e` 个输入 Token/块，Embedding 单价为 `P_e` 美元/百万 Token：

- 首年：`C_embed_first = 2.2 × T_e × P_e` 美元。
- 稳态年度：`C_embed_steady = 1.2 × T_e × P_e` 美元。

纯示例：假设每块 500 Token、`P_e=$0.02/百万 Token`（**非官方报价、非 2026-10-15 价格**），首年为 `$22`，稳态年度为 `$12`。实际费用取决于块长、模型单价、批处理折扣、重试，以及“更新 10%”是替换还是新增。

**3. 向量数据库（Pinecone 页面价格口径）**

Pinecone 官方定价页面在 findings 中列出数据库存储 `$0.33/GB/月`；Builder 为 `$20/月`（含最多 10GB），Standard 最低消费 `$50/月`，最低消费可抵扣用量。Standard/Enterprise 的读写单位价格随云与区域变化。页面未标明价格生效日期，故这些是 findings 抓取时页面可见价格，**不宣称为 2026-10-15 有效报价**。

设实际计费容量为 `S` GB，则单纯存储年费：`C_storage = S × $0.33 × 12 = $3.96S/年`。

| 假设计费容量 | 单纯存储年费 | 说明 |
|---:|---:|---|
| 10GB | $39.60 | Builder 页面列出最多 10GB；计划固定费另为 $240/年，含其他计划权益/用量，非纯存储同口径比较 |
| 100GB | $396 | 若选 Standard，最低消费年化 $600，存储费可抵扣最低消费；读写等额外用量可能增加账单 |
| 1,000GB | $3,960 | 存储本身超过 Standard 最低消费，另需计入读写单位等费用 |

文档块数不能直接换算为 GB；还需向量维度、数据类型、元数据、索引/副本开销和实际计量口径。读写单位、Egress、导入、备份、税费及区域差异未纳入上述存储情景。

**4. 缓存**

AWS findings 给出的计费口径为：ElastiCache Serverless 按存储数据 GB-小时与 ECPU 计费；节点型按节点小时计费。设 `H_gb` 为年度 GB-小时、`E_ecpu` 为年度 ECPU 数、`P_gbhr` 与 `P_ecpu` 为目标区域单价：

- Serverless：`C_cache = H_gb × P_gbhr + E_ecpu × P_ecpu`。
- 节点型：`C_cache = N × H × P_nodehr`，其中 `N` 为节点数、`H` 为每节点年度运行小时、`P_nodehr` 为节点小时单价。

纯示例：假设平均占用 20GB、全年 8,760 小时（175,200 GB-小时），年度 ECPU 为 100,000,000；再假设单价分别为 `$0.01/GB-小时` 和 `$0.000001/ECPU`，则示例成本为 `$1,852/年`（`175,200×0.01 + 100,000,000×0.000001`）。这些单价**不是 AWS 报价，也不是 2026-10-15 价格**。命中率本身不能直接推出缓存服务费，仍需测量缓存容量、请求处理量和 ECPU/节点用量。

**5. 计算资源**

AWS EC2 findings 说明按需实例按小时或秒计费，按秒计费最低 60 秒；具体价格取决于实例类型、区域、操作系统和配置。设 `N` 为实例数、`H` 为每实例年度运行小时、`P_ec2` 为实例小时单价：

`C_compute = N × H × P_ec2 + C_storage + C_network + C_other`。

纯示例：1 台实例全年运行 8,760 小时，假设 `$0.10/小时`，实例计算部分为 `$876/年`；若每天运行 8 小时、全年 365 天，则 2,920 小时、示例为 `$292/年`。示例单价不是 AWS 报价；磁盘、网络、负载均衡、监控、备份、税费和弹性扩缩容均未计入。缺少并发、延迟目标、实例规格和利用率，无法据此选型。

### 汇总公式、取舍与适用场景

总成本模型：

`C_total = C_infer + C_embed + C_vector_db + C_cache + C_compute`。

其中向量数据库需按计划最低消费抵扣、存储、读写单位及附加项核算；缓存与计算需代入目标区域和配置的实际价格。当前不能给出可信的单一总额或总成本排名。所有示例金额仅用于展示公式敏感性，不构成总成本估算或采购报价。

| 成本项 | 主要驱动 | 当前可量化程度 | 主要取舍/适用场景 |
|---|---|---|---|
| 推理 | 未命中请求、输入/输出 Token、模型单价 | Token 量可算，API 单价未确认 | 复杂任务可用能力更强模型；路由、裁剪上下文和控制输出可降费，需权衡质量 |
| Embedding | 更新块数、块长、Embedding 单价 | 块数可按假设算，单价/块长未知 | 增量重嵌入适合可追踪变更；需区分首年建库与稳态更新 |
| 向量数据库 | 实际 GB、读写单位、计划最低消费、区域 | 页面存储单价可做条件估算，实际容量未知 | 小容量可评估 Builder；更大生产负载需核对 Standard/Enterprise 最低消费、读写和附加费 |
| 缓存 | 命中率、GB-小时、ECPU 或节点小时 | 计费单位已知，实际用量/单价未知 | 高重复且允许一定时效性的查询适合缓存；个性化、实时或强新鲜度场景需谨慎 |
| 计算 | 实例数、规格、运行时长、区域、利用率 | 计费时间单位已知，规格/单价未知 | 稳定负载可评估常驻/承诺折扣；波动负载可评估弹性按需，需按峰值与延迟定规格 |

缓存命中率从 30% 提升到 90% 时，未命中请求从 700,000 降至 100,000，推理公式随之下降；但缓存服务、语义匹配 Embedding、检索校验和失效管理可能增加成本。净节省应比较“减少的推理费用”与“新增缓存及校验费用”，不能仅凭命中率判断。

## 建议

1. 先用生产日志测量缓存命中率、命中质量/新鲜度、平均输入输出 Token、重试率、峰值并发和请求分布；将 30%/70%/90% 作为敏感性情景，而非预测值。
2. 取得目标模型与 Embedding 模型在 **2026-10-15** 适用的官方 API 单价和计费规则，代入 `P_in`、`P_out`、`P_e`；本轮未能从官方页面确认逐项 API 价格。
3. 从 Pinecone 实际账单或控制台确认计费 GB、Read Units、Write Units、区域、最低消费抵扣、Egress、导入和备份；以实测容量替换 10/100/1,000GB 情景。
4. AWS 侧明确区域、ElastiCache 部署模式、平均缓存 GB、ECPU/节点规格、EC2 实例类型与运行小时，再代入公式；不要把示例单价用于采购预算。
5. 分开报告首年（含初始全库 Embedding）与稳态年度（仅更新），并明确是否包含网络、备份、监控、税费、重试和人工运维。

## 局限性

- **价格日期**：运行日期为 2026-10-15，但 findings 未证明模型/API、Pinecone 或 AWS 页面价格在该日有效。Pinecone 数字仅为页面抓取时可见价格；AWS 与模型/API 具体单价未确认。所有示例单价均为演示假设，不是官方报价。
- **来源覆盖**：本轮 findings 中可追溯的不同页面有 5 个 URL，但其中 OpenAI Business Pricing 页面不是 API 逐项定价表，Embeddings 指南也未列价格；AWS 页面部分证据来自搜索摘要，未抓取正文。未检索到足以确认模型推理与 Embedding API 单价的官方原始页面。
- **工作负载假设**：假设每个请求只调用一次生成模型，Token 数为计费 Token，不含系统提示额外量、重试、工具调用或多轮扩展；缓存命中假设直接返回结果。实际架构可能不同。
- **Embedding 与容量**：平均块长未知；每月 10% 更新按重嵌入现有块处理，未确定是替换还是新增。文档块数不能直接推导向量库 GB，缺少维度、精度、元数据、索引和副本开销。
- **资源与附加费用**：缺少 AWS 区域、实例规格、缓存用量、并发、利用率、网络、存储、备份、税费等参数；Pinecone 读写单位和区域价格也未完整量化。因此总成本只能以公式和条件情景表达，不能作为采购报价。
