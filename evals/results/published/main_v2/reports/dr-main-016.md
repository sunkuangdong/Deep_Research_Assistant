# 年处理 100 万次请求的 RAG 服务成本模型

## 背景

本报告建立一个可复算的年度成本模型：年请求量 1,000,000 次，每次平均 4,000 个输入 Token、500 个输出 Token；向量库包含 1,000,000 个文档块，每月更新 10%。成本拆分为模型推理、Embedding、向量数据库、缓存与计算资源。金额以美元计，价格日期按官方页面是否明确标注分别说明。

模型推理价格采用本轮检索到的 OpenAI 官方 API 定价页面摘要；向量数据库采用 Pinecone 官方定价页。AWS ElastiCache、EC2 及 OpenAI Embedding 官方页面虽已核验页面，但本轮返回内容未提供可用的具体单价，因此相关成本以公式和待填参数呈现，不以猜测补齐。价格页面未标明生效日期的，以下标注为“页面未标明；按本轮检索时点（2026-10-16）可见价格”，不代表锁定报价。

## 关键发现

- 年请求量为 **100 万次**；输入 Token 共 **40 亿**，输出 Token 共 **5 亿**，合计 45 亿 Token。每月更新 100,000 块，按固定基数计算全年更新 1,200,000 块，另有初始建库成本。此处将“更新”解释为每月替换/重嵌入现有库中 10% 的块，库规模保持 1,000,000 块；若实际含义是新增而非替换，则库规模和后续更新量需按新增规则重新建模。
- 可核验的模型推理成本（不含其他 RAG 组件）：无模型缓存输入计价时，o1 为 **$90,000/年**、o3-mini 为 **$6,600/年**、GPT-4o 为 **$15,000/年**。假设 50% 输入 Token 符合模型缓存输入价格条件时，分别为 **$75,000、$5,500、$12,500/年**。
- 50% 是情景假设，不是实测命中率。模型缓存输入仍会调用模型；只有应用层缓存命中并直接返回结果、绕过模型时，才可按被绕过请求减少推理调用。应用层缓存命中率未提供，因此缓存净节省无法量化。
- Embedding、向量数据库总额、缓存和计算资源无法在现有证据下给出完整金额：Embedding 单价、每块 Token 数、向量存储/读写用量、缓存规格、EC2 规格与运行时长等缺失。Pinecone 页面提供部分套餐和计费单价，可用于参数化估算。

## 证据与分析

### 1. 工作量与口径

- 年输入 Token：`1,000,000 请求 × 4,000 Token = 4,000,000,000 Token`。
- 年输出 Token：`1,000,000 请求 × 500 Token = 500,000,000 Token`。
- 每月更新块数：`1,000,000 块 × 10% = 100,000 块/月`。
- 年更新块数：`100,000 × 12 = 1,200,000 块/年`，不含初始 1,000,000 块建库。此处假设每月替换/重嵌入现有库中 10% 的块，库规模保持 1,000,000 块；若“更新”实际指新增而非替换，则需按新增规则重新计算库规模和后续更新量。

### 2. 模型推理

OpenAI 官方定价页本轮摘要列出以下价格，单位均为美元/百万 Token；页面未明确价格生效日期，故按 2026-10-16 本轮检索时点页面可见价格处理。来源：[OpenAI API Pricing](https://openai.com/api/pricing/?utm_source=rachelandreago)。

| 模型 | 输入单价（$/百万 Token） | 缓存输入单价（$/百万 Token） | 输出单价（$/百万 Token） |
|---|---:|---:|---:|
| o1 | 15.00 | 7.50 | 60.00 |
| o3-mini | 1.10 | 0.55 | 4.40 |
| GPT-4o | 2.50 | 1.25 | 10.00 |

**无模型缓存输入计价公式：**

`C_infer = (4,000,000,000 / 1,000,000 × 输入单价) + (500,000,000 / 1,000,000 × 输出单价)`

| 模型 | 输入成本 | 输出成本 | 年推理成本 |
|---|---:|---:|---:|
| o1 | $60,000 | $30,000 | **$90,000** |
| o3-mini | $4,400 | $2,200 | **$6,600** |
| GPT-4o | $10,000 | $5,000 | **$15,000** |

**模型缓存输入价格情景：**假设输入 Token 的 50% 符合官方缓存输入计价条件，输出仍全部计费。公式：

`C_infer(h) = [4,000,000,000 × ((1-h)×P_in + h×P_cached) + 500,000,000×P_out] / 1,000,000`，其中 `h=50%`。

| 模型 | 50% 输入按缓存价后的年推理成本 |
|---|---:|
| o1 | **$75,000** |
| o3-mini | **$5,500** |
| GPT-4o | **$12,500** |

该 50% 仅为敏感性假设；官方摘要未说明缓存价格的适用条件，不能假定所有重复提示词或检索上下文都符合条件。模型缓存输入仍然执行模型推理，不等于应用层缓存命中后绕过模型。若应用层缓存命中率为 `q`，且命中请求完全不调用模型，则简化推理成本为 `(1-q) × 未缓存推理成本`；本题未提供 `q`，故不虚构该情景金额。

### 3. Embedding

本轮 OpenAI 官方定价文档抓取内容未显示 Embedding 模型及单价，价格日期也无法确认；因此**未检索到可核验的官方原始页面价格条目**。来源：[OpenAI API Pricing 文档](https://developers.openai.com/api/docs/pricing)。

设 `P_e` 为 Embedding 单价（美元/百万输入 Token），`T_init` 为初始建库文本 Token 数，`T_m` 为第 `m` 月更新文本 Token 数：

- 初始建库：`C_init = T_init / 1,000,000 × P_e`。
- 年增量更新：`C_update = (Σ T_m) / 1,000,000 × P_e`。
- 年 Embedding 成本：`C_emb = C_init + C_update`。

已知更新块数，不等于 Embedding Token 数。缺少每块平均 Token、初始建库文本 Token、Embedding 模型单价及更新时是否全量重嵌入，故不能给出金额。若采用批处理，也没有本轮可核验的 Batch 折扣证据，不计入折扣。

### 4. 向量数据库

Pinecone 官方定价页列出 Starter 免费层、Builder $20/月、Standard 最低 $50/月、Enterprise 最低 $500/月。Standard/Enterprise 页面列出的部分按量价格包括存储 $0.33/GB/月、写入 $4–$4.50/百万 Write Units、读取 $16–$18/百万 Read Units、出站 $0.10/GB；读写价格随云和区域变化。页面未标明价格生效日期，按 2026-10-16 本轮检索时点页面可见价格理解。来源：[Pinecone Pricing](https://www.pinecone.io/pricing/)。

参数化月成本（简化表达，实际账单须按套餐包含额度、最低消费和区域规则核算）：

`C_vector_month = 套餐最低消费/固定费 + 超出套餐包含额度后的存储、写入、读取及出站费用`

其中按量部分可按 `存储GB×$0.33 + 写入WU/1,000,000×写入单价 + 读取RU/1,000,000×读取单价 + 出站GB×$0.10` 估算，避免将套餐最低消费与包含额度重复计费。仅有 1,000,000 个块不足以推导存储 GB、索引开销、读写单位或出站流量，因此不能给出向量数据库总额，也不能仅凭块数判断套餐容量是否足够。Standard/Enterprise 最低消费不是总成本上限。

### 5. 缓存

AWS ElastiCache 官方定价页本轮抓取未呈现可核验的实例价格、区域、规格或计费单位；价格日期未能确认。来源：[Amazon ElastiCache Pricing](https://aws.amazon.com/elasticache/pricing/)。因此缓存基础设施成本按下式保留参数：

`C_cache = 节点数 × 节点小时单价 × 运行小时 + 存储、备份、数据传输等适用费用`

需补充缓存引擎/部署模式、节点规格与数量、区域、运行时长、存储量及网络费用。缓存命中率应分别记录“模型缓存输入计价命中率”和“应用层缓存绕过模型命中率”，两者的成本效果不同；还需评估答案新鲜度、权限隔离和失效策略。

### 6. 计算资源

AWS EC2 On-Demand 官方定价页本轮抓取未呈现可核验的实例价格表、区域、规格或计费单位；价格日期未能确认。来源：[EC2 On-Demand Instance Pricing](https://aws.amazon.com/ec2/pricing/on-demand/)。

`C_compute = Σ(实例数量 × 对应区域/规格/操作系统小时单价 × 运行小时) + 存储、网络、负载均衡等适用费用`

需分别估算在线 API 服务、检索/重排、批量 Embedding 等负载，并补充实例类型、数量、区域、运行时长、弹性策略、CPU/GPU、存储和网络配置。当前不能给出计算资源金额。

### 7. 综合判断

在可核验价格范围内，o3-mini 的推理成本最低，GPT-4o 居中，o1 最高；这只是价格比较，不代表质量、延迟或任务适配性。模型推理是目前唯一可直接量化的成本项，不能把它误称为 RAG 全栈总成本。Embedding、向量库、缓存和计算资源的金额仍需补齐价格或用量参数后才能汇总。

## 建议

1. 先以 o3-mini 建立成本基准，并用实际任务评测质量、延迟和失败率；若质量不达标，再比较 GPT-4o 或 o1 的增量价值。
2. 在线监控分别记录普通输入 Token、符合模型缓存计价条件的输入 Token、应用层缓存命中并绕过模型的请求数，避免把两种缓存混为一谈。50% 模型缓存输入命中率仅作为预算情景，不应当作承诺值。
3. 通过抽样统计每块文本 Token 数、初始建库 Token 数和每月更新 Token 数，取得 Embedding 官方单价后计算初始与增量成本。
4. 从向量数据库账单或压测中取得实际存储 GB、读写单位、出站流量、云与区域，再与 Pinecone 套餐最低消费及包含额度比较。
5. 明确缓存与 EC2 的区域、规格、节点/实例数量、运行小时和弹性策略，使用对应官方价格计算器/报价补齐成本；将税费、备份、监控、日志、网络、重排、重试和运维列为额外项。

## 局限性

- OpenAI 定价页未明确价格生效日期；本报告记录为页面未标明、按 2026-10-16 本轮检索时点可见价格，价格可能变化。
- Embedding 官方页面本轮未返回可核验单价；因此 Embedding 成本只能参数化，不能给出完整金额。
- AWS ElastiCache 与 EC2 官方页面本轮未返回可核验价格表；缓存和计算资源成本无法量化。
- 向量库缺少向量维度、实际存储量、索引/元数据开销、读写单位、出站流量、区域及套餐额度适用情况。
- 每月更新 10% 按固定 1,000,000 块基数、且更新为替换/重嵌入现有块计算；若实际为新增，更新量和库规模需重新建模。每块 Token 数和重嵌入策略也未知。
- 50% 模型缓存输入计价命中率是情景假设，不是实测数据；应用层缓存绕过模型的命中率未提供，缓存净节省无法量化。
- 未计税费、折扣、备份、监控、日志、网络、重排模型、失败重试及人工运维等成本。
