# RAG 检索评估指标：情报简报

## 背景

RAG 检索评估不只是判断“有没有找到相关文档”，还涉及相关结果是否排在前面，以及检索上下文是否包含回答所需的关键证据。Recall@K、MRR、nDCG 与证据覆盖率分别观察这些问题的不同侧面，不能互相替代。指标结果也依赖相关性定义、参考集合完整度、截断位置 K 和标注粒度。

## 关键发现

- **Recall@K 衡量前 K 个结果覆盖了多少已知相关项**：`|TopK ∩ Relevant| / |Relevant|`。适合评估候选召回和检索覆盖，但分母要求尽可能完整的相关文档集合；相关项漏标会使结果不可靠。未标注项如何处理会影响评测结果，尤其当协议将未标注项视为不相关时，这属于评测数据与协议风险，并非公式本身必然如此。
- **MRR 衡量首个相关结果出现得有多靠前**：每个查询取首个相关结果排名的倒数，再对查询平均；无相关结果通常记 0。适合单一答案或首个可用结果最重要的问答/导航任务，但只反映首个相关结果位置，不代表后续证据完整性或最终答案质量，也忽略相关性等级差异。
- **nDCG 衡量前缀整体排序质量**：对靠后结果的相关性收益折扣，并相对理想排序归一化；可表达分级相关性。适合多个结果均有价值、且高相关结果应靠前的任务。必须报告相关性等级、gain 映射、折扣和 K 等约定。
- **证据覆盖率是评估目标，不是单一标准化公式**：通常关注回答所需参考信息是否在检索上下文中得到覆盖，而非排序位置。Ragas Context Recall 可按参考答案 claims、参考上下文匹配或参考上下文 ID 操作化；这些口径测量对象不同，尤其 ID 命中不等同于内容足以支持答案，不能混为一谈。
- **标注成本比较仅为条件性定性推断**：文档级相关性、分级相关性、参考片段、答案 claims 和稳定 ID 集合各有不同的构建与核验要求。现有来源没有可比较的人工工时数据，不能据此给出普遍成本排序。

## 证据与分析

### 指标含义与适用场景

| 指标 | 核心问题 | 适用场景 | 主要盲点 |
|---|---|---|---|
| Recall@K | 前 K 是否找回足够多的相关项？ | 候选召回、检索覆盖、重排器输入质量 | 不区分前 K 内的排序位置；依赖完整相关项分母 |
| MRR | 第一个相关结果出现得是否够早？ | 单一答案、首个可用结果优先的问答或导航检索 | 忽略首个相关项之后的结果；不表达多级相关性，也不代表答案正确或证据完整 |
| nDCG | 多个结果的整体排序是否合理？ | 多个相关项、分级相关性、位置重要的排序 | 不直接衡量证据是否足以支持答案；依赖一致的等级标注 |
| 证据覆盖率 | 回答所需的参考信息/事实是否在上下文中？ | RAG 检索阶段的证据充分性诊断 | 不反映证据排序位置；结果依赖参考内容及其粒度 |

Stanford《Introduction to Information Retrieval》提供检索评估、排序评估和相关性判断的基础框架；scikit-learn 官方 `ndcg_score` 文档说明 nDCG 的折扣收益与理想 DCG 归一化；BEIR 论文展示了跨任务、跨领域检索评估的基准背景。Ragas 官方文档给出 Context Recall 的多种操作化方式；RAGChecker 论文摘要支持其细粒度 RAG 诊断框架，但本次证据不足以确认其具体标注成本。MRR 公式按通行定义概述；本次 Stanford 页面抓取内容未直接呈现该公式，因此不将其作为该公式的直接出处。

### 标注成本比较

以下为依据指标所需输入和判断步骤作出的**条件性定性推断**，不是实测工时或普遍成本排序：

- **Recall@K**：单条相关性判断可以较简单，但建立尽可能完整的相关文档集合可能需要较多工作；语料大、相关项难以穷尽时，分母质量是主要成本与风险来源。实际影响还取决于未标注项处理协议。
- **MRR**：若相关性采用二元判断，标注粒度可能较直接；但要可靠确定首个相关项，仍需充分判断排序列表中更靠前的结果。未标注项处理会改变首个相关排名。
- **nDCG**：若采用分级相关性，除判断相关与否外，还需定义等级、培训标注者并控制跨查询一致性；相较二元标注是否增加多少成本，取决于候选规模和标注协议，现有来源没有实测比较。
- **证据覆盖率**：文档/片段级需要定位并核验参考证据；claim 级需要答案拆分并逐项判断支持关系；ID-based 可减少内容匹配，但依赖可靠 ID，且 ID 命中不保证内容足以支持答案。LLM 自动评估可减少部分人工判断，却仍依赖参考答案并引入拆分和评估器误差。

因此不存在适用于所有项目的固定成本排序。语料规模、证据是否分散或多跳、已有标注资产、参考答案质量、标注协议和自动化质量都会改变成本。

### 指标组合与解释

对一般 RAG 检索诊断，建议至少并列报告 **Recall@K 与证据覆盖率**：前者回答相关检索单元是否进入候选前缀，后者回答上下文是否支持参考答案中的必要信息。若首个可用证据的出现位置重要，可加 MRR；若多个证据均有价值且相关性有等级，可加 nDCG。MRR 不应替代证据覆盖率，因为它不衡量后续证据是否齐全；nDCG 也不直接回答证据是否足以支持答案。报告中应明确 K、相关性/证据单位、参考集合构建方式、未标注项处理、平均方式，以及 nDCG 的等级与 gain 约定。

## 建议

1. **先按业务目标选指标，不要追求单一总分。** 候选覆盖优先看 Recall@K；首个可用结果优先看 MRR；多级相关性和整体排序优先看 nDCG；RAG 证据充分性则单独看证据覆盖率。
2. **把标注协议作为指标定义的一部分。** 固定相关性单位、证据粒度、参考集合来源、未标注项处理、K 值、平均方式及 nDCG gain 映射；否则同名指标也可能不可比。
3. **按成本与风险分层建设评测集。** 可先用已有文档相关性判断评估排序，再对代表性问题建立参考答案/证据片段或 claim 级标注，抽样核验自动评估器；对高风险或多跳问题增加人工证据核验。
4. **同时报告分数与标注覆盖/质量说明。** 尤其披露相关文档集合是否穷尽、参考答案是否覆盖关键事实，以及 LLM 评估器的验证方式，避免把标注缺口误读为检索系统缺陷或优势。

## 局限性

- 本次未检索到可核验的 TREC 官方评估指南页面，因此没有用 TREC 来源支撑标注成本结论；也未检索到可直接比较不同指标人工工时的实证数据。
- Stanford 页面在本次 findings 中未被记录为直接呈现 MRR 公式；MRR 采用通行定义概述，来源支持边界已在调研材料中说明。
- Recall@K、MRR 的平均方式及无相关结果处理，nDCG 的 gain、折扣和截断约定可能因实现而异；跨系统比较前需统一协议。
- Ragas 的 claim 支持、参考上下文匹配和 ID 命中是不同操作化口径；证据覆盖率并非单一标准化定义。
- RAGChecker 仅核实论文摘要层面的细粒度诊断框架与评估挑战，未核实全文标注流程或成本数据。成本比较因此是定性推断，不应解读为普遍的成本排名。
