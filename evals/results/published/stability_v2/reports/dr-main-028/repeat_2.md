# RAG 检索评估指标：含义、适用场景与标注成本

## 背景

RAG 检索评估不只是判断“有没有找到相关文档”，还涉及相关证据是否覆盖充分、是否排在靠前位置，以及检索上下文是否包含回答问题所需的信息。Recall@K、MRR、nDCG@K 与证据覆盖率分别从不同角度衡量这些问题，不能视为可互换的单一分数。

本报告中的“证据覆盖率”主要指 RAGAS Context Recall 所代表的答案所需信息覆盖：参考答案中的 claims（可拆分核验的事实陈述）有多少能由检索上下文支持。下文将其简称为 Context Recall。它与传统文档级 Recall@K 的测量单位不同。

## 关键发现

- **Recall@K 衡量已知相关文档的检出覆盖。** 对查询 q，Top K 中相关文档数除以已知相关文档总数。适合检查召回器是否漏掉可用证据，尤其适用于重排或生成之前。它依赖较完整的相关文档集合；标注不完整会影响分母和分数。
- **MRR 衡量首个相关结果出现得有多早。** 按标准排序评估定义，每个查询取首个相关结果排名的倒数，无相关结果记 0，再对查询求平均。适合“尽早找到一个有效证据即可”的任务，但不反映首个命中之后的覆盖数量或相关性等级。本轮可核验材料对 MRR 公式的直接支持较弱，故此处将其作为标准定义说明，而非本轮来源直接验证的结论。
- **nDCG@K 衡量分级相关性与排序位置。** 它对排名靠后的相关结果施加折扣，并相对于理想排序归一化；适合区分高度支持与部分相关的片段、且靠前结果更重要的场景。它需要分级相关性判断，标注规范和一致性控制会增加成本。
- **Context Recall 衡量回答所需信息是否进入检索上下文。** RAGAS Context Recall 可按参考答案 claims 中被上下文支持的比例计算；也提供基于参考上下文或文档 ID 的路径。不同路径的测量单位和输入不同，分数不应未经校准直接比较。
- **标注成本没有固定数值或已验证的普遍排序。** 成本取决于查询数、候选池大小、标注深度、相关性定义、评估截断点、参考数据准备与校验等。Recall@K 的完整分母要求可能扩大标注覆盖；MRR 在首个命中较早且判断可靠时可能减少后续判断，但无命中查询仍需检查到评估深度；nDCG 需要分级判断；Context Recall 则需要参考答案 claims、参考上下文或文档 ID 等基准数据。以上是基于指标输入要求的定性分析，不是成本实测。

## 证据与分析

### 指标对照

| 指标 | 核心问题 | 适用场景 | 标注/数据成本驱动因素 | 主要局限 |
|---|---|---|---|---|
| Recall@K | 已知相关文档中有多少进入 Top K？ | 召回阶段漏检诊断、候选召回器评估 | 需要相关文档集合及较完整分母；候选池和评估深度影响标注量 | 未标注相关项或不完整参考集合会扭曲分数 |
| MRR | 第一个相关结果有多靠前？ | 只需尽早找到一个有效证据/来源 | 二元相关性判断；在首个命中较早且判断可靠时可能减少后续判断，但确认无命中需检查到截断点 | 忽略首个命中之后的相关项数量、覆盖率和等级；本轮来源对公式的直接支持较弱 |
| nDCG@K | 分级相关结果是否排在更重要的位置？ | 相关性有等级差异、靠前结果更重要 | 需要分级相关性标注及一致性控制 | 依赖等级定义；单独不能说明相关证据是否全部覆盖 |
| Context Recall / 证据覆盖率 | 回答所需信息有多少被检索上下文支持？ | 检查检索上下文是否遗漏答案所需信息 | 需要参考答案/claims、参考上下文或文档 ID；自动判断仍需校验基准数据 | 受参考完整性、claim 拆分、模型判断或匹配方式影响；不衡量排序、噪声或生成质量 |

### 示例：同一检索结果为何得到不同分数

假设单个查询的 Top 3 二元相关性标签为 `[0, 1, 1]`，已知相关文档共 2 个且都在 Top 3；另假设参考答案有 2 条必要 claims，检索上下文支持其中 1 条。采用二元 gain 和 `gain/log₂(rank+1)` 折扣计算 nDCG：

- Recall@3 = 2/2 = **100%**：已知相关文档都被检出。
- MRR = 1/2 = **0.5**：首个相关结果在第 2 位。
- nDCG@3 ≈ **0.8155**：相关结果虽都出现，但首位是不相关项，排序不理想。
- Context Recall = 1/2 = **50%**：参考答案所需 claims 中只有一半被上下文支持。

该示例仅用于说明测量对象差异，不是实测结果。它显示 Recall@K 高并不保证排序靠前，也不保证答案所需证据完整；Context Recall 以 claims 为单位，不能替代文档级召回或排序指标。

### 标注成本的实际解释

成本比较应以“每个查询需要判断多少候选、判断粒度多细、参考基准如何构建”为核心，而不是给指标贴固定的高低成本标签。二元相关性判断在任务定义清楚时可能比多级相关性判断更简单，但 Recall@K 的完整分母要求可能扩大标注池；MRR 在首个命中后可停止判断，却不能把未检查结果直接当作不相关；nDCG 的等级标注需要明确准则和一致性检查。Context Recall 若用参考答案 claims 作为代理，可减少逐条标注证据段落的工作，但参考答案本身仍需准备和校验；若采用参考上下文或 ID，则成本转移到这些基准数据的整理。上述均为定性推论，现有来源没有提供工时或费用对照。

### 综合判断

四项指标互补：Recall@K 看“找全多少”，MRR 看“第一个命中来得多早”，nDCG 看“不同等级的相关结果是否靠前”，Context Recall 看“回答所需信息覆盖多少”。建议按系统目标并列报告，而非合成未经解释的总分。Recall@K、nDCG 与 Context Recall 的定义和输入依赖由所列教材、官方文档及论文页面支持；MRR 公式在本轮来源中缺少直接支持，按标准定义说明。成本驱动因素及组合建议是基于测量对象的定性分析，不是来源提供的成本实测。

## 建议

1. **以避免漏检为首要目标时**，报告 Recall@K，并明确 K、相关性定义、候选池构造和参考相关集合的完整性。
2. **以尽早出现一个有效证据为目标时**，补充 MRR；同时说明无命中查询的处理方式和评估截断深度，并将其定义视为标准指标说明而非本轮来源直接验证。
3. **需要区分证据强弱并重视靠前位置时**，使用 nDCG@K，预先定义分级相关性标准，并检查标注者一致性。
4. **需要诊断答案所需信息是否被检索上下文覆盖时**，使用 Context Recall；明确采用 claims、参考上下文还是文档 ID 路径，并报告参考数据的来源与校验方式。
5. **建立分层评估组合**：至少并列报告 Recall@K 与 nDCG@K；按业务需要增加 MRR 和 Context Recall。所有系统使用同一查询集、相同 K 和一致的标注协议，并披露标注池、评估深度及参考数据准备成本。
6. **不要把自动化等同于零标注成本。** LLM 评估可减少部分人工判断，但参考答案、claims、参考上下文或文档 ID 的构建与抽查仍需资源。

## 局限性

本轮来源没有提供可比较的人工标注工时、货币成本或成本实验，因此成本只能定性讨论，不能给出固定人时或费用。MRR 的公式在本轮 findings 中缺少直接来源覆盖，结论按标准定义使用，证据强度低于 nDCG 与 RAGAS Context Recall 的文档定义。RAGAS 不同 Context Recall 路径的测量单位不同；参考答案或相关文档集合不完整会影响覆盖结论。示例依赖明确列出的二元标签、K 值、折扣形式和 claims 假设，不能外推为真实系统表现。ARES 论文仅作为自动化评估与人工标注背景，现有证据不足以证明其定义了与 Context Recall 等价的指标。
