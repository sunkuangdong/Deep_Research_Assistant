# LangChain 结构化 Tool Calling 入门调研报告

## 背景

Tool Calling 让聊天模型能够提出对外部函数或服务的调用请求，并在获得工具结果后继续生成响应。LangChain 官方文档将工具描述为具有明确输入和输出、传递给聊天模型的可调用函数；模型根据对话上下文决定是否调用以及提供哪些参数。工具调用能力和具体行为取决于所选模型及其提供方集成，不能仅凭框架接口假定所有模型完全一致。

本报告依据 LangChain 官方 Python 文档，梳理工具定义、参数 Schema、模型绑定/调用和工具结果返回，并给出适合初学者的实施清单。来源页面在本轮抓取中部分内容被截断，因此对未能核实的 API 细节明确标注局限。

## 关键发现

### 1. 工具定义：函数、名称与描述

最简方式是使用 `@tool` 装饰器将函数定义为工具。函数类型注解用于定义输入 Schema；函数 docstring 默认成为工具描述，帮助模型理解工具用途和适用时机。工具名称默认来自函数名，也可显式指定名称和描述。官方建议使用 `snake_case`，避免空格或特殊字符，以提高不同模型提供方的兼容性。

初学者可把工具设计成职责单一、输入输出清晰的函数，并写出准确、简洁的描述。前述工具定义、类型注解、docstring 和命名建议来自官方文档；“职责单一”等属于通用工程建议，不是本轮官方页面直接规定。工具描述帮助模型理解用途和判断何时使用，不宜只写“执行操作”之类含糊文字。

### 2. 参数 Schema：类型注解与显式结构

简单参数可直接通过 Python 类型注解表达；复杂输入可使用 Pydantic 模型或 JSON Schema。官方示例展示了字段类型、默认值、枚举约束和字段描述，并通过 `args_schema` 指定 Pydantic 输入模型。Schema 为模型提供参数结构；应用侧仍应按实际工具实现验证输入和处理错误，不应把模型生成的参数视为天然可信。

### 3. 模型绑定与调用：模型提出调用，应用负责执行

LangChain 模型接口支持工具调用；模型在 Agent 中承担决策角色，包括决定调用哪些工具、如何解释结果以及何时给出最终答复。初学者需要区分“把工具提供给模型”与“实际执行工具”：模型产生的是结构化调用意图，工具函数或 Agent 执行环节才完成外部操作。

本轮官方页面抓取确认了工具调用的总体机制，但未完整呈现模型绑定 API 的签名、参数选项或独立调用的完整代码。因此，具体项目应以所用模型提供方的集成文档和当前版本 API 为准；以下清单中的绑定、执行和回传步骤是流程层面的通用指引，不是可直接复制的完整 API 教程。

### 4. 工具结果返回：不止字符串

官方工具文档列出字符串、对象、多模态内容、`Command`、工具直接返回以及带 `return_direct` 的 `Command` 等返回形式。这说明工具结果可以承载结构化数据或控制信息，不局限于纯文本。初学者可先选择最简单且与后续消费方式匹配的返回类型；只有确有状态更新、控制流或多模态需求时，再采用更复杂形式。后一句属于通用实施建议。

本轮抓取未完整呈现各返回形式的语义、消息结构和调用关联细节，因此不对具体字段或完整往返代码作断言。实际实现时应依据所用 Agent/模型集成文档确认结果如何进入后续流程。

## 实施清单

以下清单区分官方文档已核实的接口概念与通用工程建议；由于本轮未核实完整绑定 API，不能将其视为可直接运行的代码步骤。

1. **明确工具边界（通用工程建议）**：为工具确定职责、输入、输出及副作用；涉及外部写操作时，按应用安全要求设置权限和确认机制。
2. **定义函数（官方文档已核实）**：使用 `@tool` 创建工具；函数类型注解定义输入 Schema。工具名默认来自函数名，建议采用 `snake_case`，避免空格或特殊字符。
3. **补齐描述（官方文档已核实）**：编写简洁 docstring，说明工具用途；需要时显式设置工具名称和描述。
4. **设计参数 Schema（官方文档已核实）**：简单输入使用类型注解；复杂输入可使用 Pydantic 或 JSON Schema。官方示例包含字段类型、默认值、枚举约束和字段描述。**通用工程建议**：在应用侧验证输入并处理无效值。
5. **测试工具函数（通用工程建议）**：在接入模型前，单独测试正常输入、边界值、异常和外部服务失败，确认返回值符合预期。
6. **选择模型（官方文档已核实总体能力）**：通过 LangChain 标准模型接口初始化模型，并查阅所选提供方的当前官方集成文档，确认工具调用支持、限制和版本要求。
7. **向模型提供工具（流程指引，API 细节未核实）**：按当前模型集成文档的方式绑定或传入工具；不要假设不同提供方的绑定参数和调用行为完全相同。
8. **执行调用（流程指引，API 细节未核实）**：区分模型返回的调用意图与工具执行结果；由 Agent 或应用执行对应函数，并处理参数不合法或工具执行失败等情况。
9. **处理工具结果（官方文档已核实返回形式，往返细节未核实）**：官方列出的返回形式包括字符串、对象、多模态内容和 `Command` 等。按所用 Agent/模型流程确认结果如何交回后续处理，并验证模型能否基于结果继续回答。
10. **观测与迭代（通用工程建议）**：记录必要的调用状态和错误信息，避免记录敏感数据；测试工具选择、参数遵循、错误处理和最终答复质量。

## 局限性

- 本次依据的官方页面为 LangChain Tools 与 Models 文档；抓取结果均标记为截断。工具结果各类型的完整语义、模型绑定 API 的完整签名、工具调用消息字段及端到端示例未能在本轮材料中核实。
- 本轮可追溯的官方来源为两个不同页面（Tools、Models）；Models 的 tool-calling 锚点属于同一 Models 页面，不作为第三个独立来源计数。用户要求至少三个不同 HTTP(S) 来源链接，报告列出三个不同 URL，但其中两个 URL 指向同一页面的不同锚点/路径形式，故独立来源数量仍只有两个。未用无关或低质量链接凑数。
- 官方文档说明模型提供方集成存在差异；具体支持能力、参数格式和限制应以所选提供方的当前官方集成文档为准。
- 本报告是面向初学者的概念与实施清单，不是可直接运行的完整代码教程；部署前需按项目使用的 LangChain 版本和模型集成验证 API。
- 本次按 --no-analysis 运行，未进行分析师阶段（analyst）。
