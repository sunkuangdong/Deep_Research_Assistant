# LangChain 结构化 Tool Calling 入门调研报告

## 背景

Tool Calling 让聊天模型能够提出对外部函数或服务的调用请求，并在获得工具结果后继续生成响应。LangChain 官方文档将工具描述为具有明确输入和输出、传递给聊天模型的可调用函数；模型根据对话上下文决定是否调用以及提供哪些参数。工具调用能力和具体行为取决于所选模型及其提供方集成，不能仅凭框架接口假定所有模型完全一致。

本报告依据 LangChain 官方 Python 文档，梳理工具定义、参数 Schema、模型绑定/调用和工具结果返回，并给出初学者实施清单。来源页面在本轮抓取中部分内容被截断，因此对未能核实的 API 细节明确标注局限。

## 关键发现

### 1. 工具定义：函数、名称与描述

最简方式是使用 `@tool` 装饰器将函数定义为工具。函数类型注解用于定义输入 Schema；函数 docstring 默认成为工具描述，帮助模型理解工具用途和适用时机。工具名称默认来自函数名，也可显式指定名称和描述。官方建议使用 `snake_case`，避免空格或特殊字符，以提高不同模型提供方的兼容性。

初学者可把工具设计成职责单一、输入输出清晰的函数，并写出准确、简洁的描述。前述工具定义、类型注解、docstring 和命名建议来自官方文档；“职责单一”等属于通用工程建议，不是本轮官方页面直接规定。工具描述帮助模型理解用途和判断何时使用，不宜只写“执行操作”之类含糊文字。

### 2. 参数 Schema：类型注解与显式结构

简单参数可直接通过 Python 类型注解表达；复杂输入可使用 Pydantic 模型或 JSON Schema。官方示例展示了字段类型、默认值、枚举约束和字段描述，并通过 `args_schema` 指定 Pydantic 输入模型。Schema 不只是文档：它为模型提供参数结构，也为应用侧输入处理提供明确约束。应避免把多个参数塞进一个含糊字符串，并为字段提供有意义的类型和描述。

### 3. 模型绑定与调用：模型提出调用，应用负责执行

LangChain 模型接口支持工具调用；模型在 Agent 中承担决策角色，包括决定调用哪些工具、如何解释结果以及何时给出最终答复。初学者需要区分“把工具提供给模型”与“实际执行工具”：模型产生的是结构化调用意图，工具函数或 Agent 执行环节才完成外部操作。

本轮官方页面抓取确认了工具调用的总体机制，但未完整呈现模型绑定 API 的签名、参数选项或独立调用的完整代码。因此，具体项目应以所用模型提供方的集成文档和当前版本 API 为准，不应把某个提供方的调用细节泛化为所有模型通用行为。

### 4. 工具结果返回：不止字符串

官方工具文档列出字符串、对象、多模态内容、`Command`、工具直接返回以及带 `return_direct` 的 `Command` 等返回形式。这说明工具结果可以承载结构化数据或控制信息，不局限于纯文本。初学者应先选择最简单且与后续消费方式匹配的返回类型；只有确有状态更新、控制流或多模态需求时，再采用更复杂形式。

本轮抓取未完整呈现各返回形式的语义、消息结构和调用关联细节，因此不对具体字段或完整往返代码作断言。一般实施时应验证工具结果确实进入后续模型/Agent 流程，并检查错误、空结果和非预期类型的处理。

## 实施清单

1. **明确工具边界**：为每个工具确定单一职责、输入、输出及副作用；外部写操作应设置必要的权限和确认机制。
2. **定义函数**：使用 `@tool` 创建工具；函数名采用 `snake_case`，避免空格和特殊字符。
3. **补齐描述**：编写简洁 docstring，说明工具做什么、何时使用、参数含义及重要限制；必要时显式设置工具名称和描述。
4. **设计参数 Schema**：简单输入使用类型注解；复杂输入使用 Pydantic 或 JSON Schema。为字段设置类型、必要性、默认值、枚举范围和清晰描述，并验证无效输入。
5. **实现并测试工具函数**：先脱离模型直接测试正常输入、边界值、异常和外部服务失败，确认返回值稳定且可序列化/可消费。
6. **选择支持工具调用的模型**：通过 LangChain 标准模型接口初始化模型，并核对所选提供方的工具调用支持、限制和版本要求。
7. **将工具提供给模型**：按当前模型集成文档的方式绑定或传入工具；不要假设所有提供方的绑定参数和调用行为完全相同。
8. **处理调用请求**：区分模型返回的工具调用意图与工具执行结果；由 Agent 或应用执行对应函数，并处理模型未调用工具、调用参数不合法或工具执行失败等情况。
9. **回传并验证结果**：按所用 Agent/模型流程将工具结果交回后续处理；确认模型能基于结果继续回答。根据需求选择字符串、对象或其他官方支持的返回形式。
10. **观测与迭代**：记录模型请求、工具名称、参数、执行状态和结果摘要；避免记录敏感数据。用真实任务测试工具选择准确性、Schema 遵循情况、错误恢复和最终答复质量。

## 局限性

- 本次依据的官方页面为 LangChain Tools 与 Models 文档；抓取结果均标记为截断。工具结果各类型的完整语义、模型绑定 API 的完整签名、工具调用消息字段及端到端示例未能在本轮材料中核实。
- 官方文档说明模型提供方集成存在差异；具体支持能力、参数格式和限制应以所选提供方的当前官方集成文档为准。
- 本报告是面向初学者的概念与实施清单，不是可直接运行的完整代码教程；部署前需按项目使用的 LangChain 版本和模型集成验证 API。
- 本次按 --no-analysis 运行，未进行分析师阶段（analyst）。
